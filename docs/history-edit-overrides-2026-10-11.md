# History 消息编辑覆盖验收

普通消息编辑直接加载 history.db 中已物化的消息状态，再应用新增的覆盖事件；回复自身编辑保留回复发生时的快照。原消息身份、发送者和时间、删除标记、synthetic self-send / authoritative echo 语义继续由共用 Projection reducer 维护。

恢复到历史时间、回填旧来源或发现已保存前缀指纹不一致时，只读取影响有效状态的原消息、最后一次 edit、delete 和必要 echo 正文。中间 edit 的正文不再解码或计入状态条目预算。完整来源证据指纹仍按原算法逐条流式计算，并在输出事务中保存；它是私有同步元数据，不是对用户展示的编辑历史。普通新增编辑复用前缀指纹，仅追加后缀。

没有新增原库或 History 字段/迁移，没有改变 generation 和指纹格式，也没有提高默认预算。已有 History 可原地继续消费。本轮不清理原始归档中的 edit 事件。

## 回归

修改前，300 次短文本编辑后的新增消费触发默认 256 条目预算，阻塞其他群的新消息；回复自身编辑还会重新读取原消息和父消息。新增测试先复现上述行为，再验证修复。

- 300 次编辑初建后再追加 300 次编辑，以及其他群的新消息：正常消费，与完整参考输出一致，spy 确认普通编辑不读取旧事件正文。
- 回复自身编辑：保留已有快照，不重新读取父消息或原消息。
- 父消息 400 次编辑后插入历史时间的回复，再删除/编辑父消息：恢复回复发生时的第 250 次内容，保留原消息元数据和删除状态，匹配完整参考构造。
- 既有媒体补齐、来源回填、回复依赖、echo、重启及事务失败回归均通过。

最终检查：`pnpm typecheck`、`pnpm lint:fix`、`pnpm test:run --maxWorkers=1 --no-file-parallelism --testTimeout=60000`、`pnpm build`；54 文件 / 534 项测试通过。见 [检查日志](history-edit-evidence/checks.txt)。

## 规模与真实归档

在无网络隔离 Docker 中运行最终编译 worker，1 CPU / 1536 MiB，沿用默认限额。token 计数沿用 tiktoken 0.14.0 / o200k_base 正文 fixture。

| 用例 | 正文 token | 条目 | 耗时秒 | 峰值 RSS MiB |
| --- | ---: | ---: | ---: | ---: |
| 长回复链 + 重启 | 1,002,000 | 1,001 | 47.44 | 111.38 |
| 普通归档 + 重启 | 1,002,000 | 1,001 | 32.79 | 113.86 |
| 单条大消息 | 1,000,000 | 1 | 3.52 | 240.11 |
| 单条大 TR | 1,000,000 | 3 | 2.93 | 127.09 |

四个用例的完整正文、回复与搜索校验均无差异，worker 无错误。见 [百万 token 证据](history-edit-evidence/million.json)。

真实归档一致快照副本包含 1,057 events / 196 TR；初建中终止 worker，向副本追加数据后恢复，最终 4 群 / 1,529 条目、参考差异 0，SQLite / FTS 校验通过，原库行与 schema 不变。见 [归档证据](history-edit-evidence/real-online.json)。以上是隔离验收；正式部署验证另存于本地 runtime 记录。
